Market Data Pipeline

How prices, company data and news for about 16,000 stocks on 11 exchanges are collected, stored and turned into signals for the MarketPulse dashboard.

3 CDK stacks9 state machines11 Lambdas5 Fargate tasks16 Athena tables

How it fits together

Everything runs on schedules. Each schedule starts a Step Functions state machine, which fans work out to Lambda functions or Fargate tasks. They write Parquet files to one S3 bucket, the Glue catalog makes those files queryable in Athena, and the signal engine and dashboard read through Athena.

How a day's prices get collected

The stock pipeline runs every 2 hours but collects each exchange's day exactly once, after it is final.

Check every exchange in its own time zone

check-market-hours asks: was today a trading day there (not a weekend or listed holiday), has it been at least 2 hours since that market's close, and is this day not yet recorded in state/stocks_daily.json? Most checks find nothing and stop. Daylight saving needs no handling.

Plan chunks

Each ready exchange's ticker list is split into chunks of 400. The request covers only days not yet collected: normally just today, or the missed days after an outage.

Collect in parallel

Up to 10 collect-stocks Lambdas run at once. Each fetches 50 tickers at a time with 4 parallel requests, a 60-second cap per batch and a stop before the Lambda time limit. It writes one Parquet file per trading day: stocks_daily/date=…/exchange=…/part-…. Retries overwrite the same file.

Mark done only on full success

An exchange-day is recorded as collected only if every chunk succeeded. A failed chunk, a time-out or an empty Yahoo response leaves it pending, and the next 2-hourly check retries it.

Make it queryable

New partitions are registered in Glue straight away, so the data is in Athena within minutes of the run finishing.

Design decisions

Daily bars, not intraday

Snapshots every 2 hours were neither live nor a full intraday series. One final bar per stock per day is what screening and backtesting need.

Chunked fan-out

Exchanges are split into 400-ticker chunks so no Lambda runs near its 5-minute limit, and one bad chunk never cancels the rest.

One Fargate task per exchange

Heavier per-stock jobs run as separate tasks, all exchanges at once. Each task gets its own IP, which spreads Yahoo rate limits.

ECS tasks referenced by name

State machines call tasks by family name, so changing a task image never conflicts with cross-stack exports.

Ticker lists match Trading 212

Lists keep common shares and warrants, and drop SPAC units and rights, which Trading 212 doesn't offer.

Pinned libraries

Container images pin yfinance 0.2.61, pandas 2.2.3 and pyarrow 25.0.0, matching the Lambda layer.

Infrastructure is defined in AWS CDK (Python) as three stacks: MarketDataStorage (S3, Glue, DynamoDB), MarketDataCompute (Lambdas, Fargate task definitions) and MarketDataOrchestration (state machines, schedules). Source: github.com/eazubike/market-data-pipeline.
